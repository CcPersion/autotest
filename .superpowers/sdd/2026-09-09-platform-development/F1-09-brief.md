# F1-09 基础结果采集和原生报告

## 目标

把 F1-08 的运行终态和 JMeter JTL 结果转换为平台自己的结构化步骤报告，先覆盖单接口运行；JTL、JMX 和 JMeter 日志只作为运行制品，不作为页面展示模型。

## 本轮必须交付

- Runner 解析 JMeter CSV JTL，按 `HTTP Request [stepId]` 关联稳定步骤标识。
- 采集状态码、响应描述、耗时、最终成功标记、失败原因和脱敏 URL；敏感查询参数不得进入报告。
- Platform API 保存 `step_results`，以 `(runId,resultKey)` 幂等，重复回传不产生重复步骤。
- 提供运行报告查询接口，返回运行状态和步骤结果；跨项目运行 ID 必须 404。
- 成功、断言失败、连接失败三类 JTL 夹具测试；正文默认截断，不接入 SSE、导出、Allure、场景树和复杂监听器。

## 明确不做

- 不新增 JMeter 插件、脚本组件、JTL 之外的脆弱控制台解析。
- 不把 JTL 原始内容直接透传给浏览器；报告字段统一脱敏和长度限制。
- 不实现 F1-10 完整 Playwright 闭环，不宣称部署级 Runner 常驻入口已完成。
