# F2-10 测试集合与组合场景 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 支持按固定顺序维护接口用例/场景成员，选择环境并生成已解析的测试集合执行计划。

**Architecture:** 测试集合是项目级资产，成员只保存 API_CASE 或 SCENARIO 引用、顺序和启用状态；运行集合时在一个事务内读取集合、环境和成员，复用已有场景计划解析器生成 `suiteSteps`，再交给现有 RunService 创建 `TEST_SUITE` 运行记录。Runner 先顺序执行集合成员，成员内部沿用已有 API/场景执行语义；场景步骤进入 Runner 前加上 `memberId/` 作用域，报告通过成员元数据和稳定结果键保留顺序证据。

**Tech Stack:** Java 17、Spring Boot、JdbcTemplate、PostgreSQL/Flyway、Jackson、Vue 3、TypeScript、Vitest。

**Spec:** `docs/requirements/01-产品需求规格说明书.md` 第 6.11 节；`docs/tasks/01-开发任务清单.md` F2-10。

## Global Constraints

- 测试集合只允许引用 `API_CASE` 或 `SCENARIO`，运行入口仍只有接口用例、场景、测试集合。
- 成员顺序由非负 `position` 决定，运行计划保存解析后的引用内容，不保存密钥明文。
- 集合运行必须选择同项目且未归档的环境；集合/成员/引用缺失时拒绝创建运行。
- 首版不增加租约、fencing、并发调度和版本快照；不改变已有 API/场景运行语义。

## Self-Review Checklist

- 只新增测试集合相关表、接口、页面和 Runner 分支；没有引入 Redis、Kafka、租约或发布版本系统。
- API_CASE 与 SCENARIO 的解析仍使用已有字段和变量/断言/清理语义，集合仅负责顺序编排。
- 计划 JSON 只保存密钥引用，不保存密钥明文；旧运行入口与报告接口保持兼容。
- 集合运行提交后跳转真实报告页；报告页对 `PENDING/RUNNING` 运行轮询，直到终态或组件卸载。
- 步骤结果接口返回集合成员 `memberId`；报告页可按成员过滤步骤树与证据面板，且“全部成员”视图保持兼容。
- 真实 Playwright 已覆盖创建集合、选择 API_CASE 与基础 SCENARIO 成员、保存和提交运行；复杂集合夹具已补充“登录→提取→业务→SQL→Redis→清理”主链、清理后 Redis 哨兵和重启后报告恢复证据；定时任务、SSE、多 Runner 调度及强制终止清理状态仍不在本任务范围。
