# F2-06 JDBC 数据源与 SQL 步骤开发计划

## 目标

在现有场景编排和 Runner 首片能力上，增加可复用的数据源资产与 SQL 步骤，使一个场景可以安全地查询 PostgreSQL/MySQL，并对结果进行提取和断言。实现必须遵守现有单租户、密钥引用、不可在运行快照中保存明文凭据的约束。

## 范围与不做事项

本阶段只实现 PostgreSQL、MySQL、SELECT 查询、受控参数变量、行/列提取、行数/字段/集合断言、连接测试和写 SQL 双确认门禁。不实现 Redis、条件/循环、嵌套场景、任意脚本、存储过程、自动写 SQL，也不改变已有 HTTP 执行语义。

## 实施步骤

1. **数据源持久化与契约**
   - 新增 `data_sources` 迁移、记录模型、仓储、请求/响应 DTO。
   - 数据源归属项目和环境，类型限定 `POSTGRESQL`/`MYSQL`；凭据只保存 `secretRef`，不保存密码明文。
   - 提供 CRUD、归档、连接测试接口；连接测试使用临时解析的密钥，不回显凭据。
   - 为字段约束、修订冲突、密钥泄漏和归属校验增加后端测试。

2. **SQL 步骤领域契约**
   - 定义 SQL 步骤配置：数据源、SQL 文本、变量参数、提取器、断言、`allowWrite` 与二次确认标志。
   - 采用保守的 SQL 分类器；非查询语句只有在显式允许且二次确认通过时才能进入运行计划，未确认写 SQL 必须在服务端拒绝。
   - 校验数据源属于当前项目/环境，变量和列名格式合法，断言类型与参数完整。
   - 增加场景计划构建测试，验证密码只以密钥引用存在、写 SQL 门禁和运行快照不可变。

3. **Runner JDBC/JMeter 执行**
   - 先以受控 Java JDBC 执行器完成查询、提取和断言的真实语义切片，避免把凭据写入 JMX；随后补充 JMeter JDBC 配置与采样器映射，并以同一结构化计划兼容两种执行路径。
   - 执行前解析变量和受控密钥引用；JTL/报告只记录数据源名称、SQL 摘要、耗时、行数、断言结果，不记录密码。
   - 支持行数、字段值、集合包含/相等等首批断言，支持把指定行列写入运行上下文。
   - 为成功、查询失败、断言失败和未确认写 SQL 增加 Runner 单元/契约测试。

4. **Web 配置与编排**
   - 在环境页实现 JDBC 数据源列表、新建/编辑、连接测试和密钥引用选择。
   - 在场景页实现 SQL 步骤编辑器：数据源选择、SQL、参数、提取器、断言、写操作二次确认；未确认写 SQL 显示阻断原因。
   - 保留现有 HTTP/WAIT/API_CASE 交互，不扩大到 Redis 和控制流。

5. **真实集成与交付证据**
   - 使用 Testcontainers 分别验证 PostgreSQL 和 MySQL 连接、查询、提取、断言。
   - 运行最小后端/Runner/Web 门禁，执行一次真实场景并核对报告脱敏、错误分类和清理。
   - 更新 `progress.md`，明确完成项、未完成项和下一项 F2-07 边界。

## 验收条件

- PostgreSQL 与 MySQL 均可通过数据源连接测试并执行 SELECT。
- 未同时满足允许写入和二次确认的写 SQL 不得进入可执行计划。
- SQL 参数遵循现有变量解析规则；提取值可供后续步骤使用。
- SQL 结果断言失败与连接/执行失败分类不同，报告不含密码、密钥值或完整敏感 SQL 参数。
- 数据源跨项目/环境引用、修订冲突、未知字段和无效断言均有可重复测试。
- 现有 F0/F1/F2-01～F2-05 门禁保持通过。
