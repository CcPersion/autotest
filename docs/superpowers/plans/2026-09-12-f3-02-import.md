# F3-02 Curl 与 OpenAPI 导入实施计划

## 目标

将常见 Curl 单接口和 OpenAPI 3 文档转换为平台现有接口定义/接口用例结构，提供可审阅的预览与冲突处理；预览阶段不写库，只有确认接口在一次事务中落库。

## 范围与边界

- 支持 Curl 的常用方法、URL、查询参数、Header、Cookie、JSON/TEXT/URLENCODED body；拒绝 Shell 替换、命令拼接、文件上传和无法定位的语法，并返回字段位置。
- 支持 OpenAPI 3 JSON/YAML 的 `servers`、`paths`、parameters、requestBody、基础 response；每个 operation 生成一个接口定义和一个默认接口用例。
- 预览返回新增、更新、跳过三类差异；默认不覆盖已有资产，确认请求必须携带预览令牌和项目 revision。
- 不执行导入文本中的脚本、表达式、远程引用或外部网络请求；不在本任务实现 AI 页面、字段级 Diff 或自动运行。

- [x] 实现 Curl 解析、OpenAPI 解析、统一中间结构与字段定位错误。
- [x] 实现预览服务、名称/URL 冲突分类、一次事务确认落库和幂等令牌。
- [x] 暴露项目级 REST 接口，并确保预览和非法输入不改变数据库。
- [x] 执行定向测试、真实 PostgreSQL 回归和根目录门禁，记录剩余边界。

## 交付验收

- 20 个 Curl 夹具和 3 份 OpenAPI 夹具可解析或得到带路径的错误。
- 预览前后数据库行数、revision 不变；确认只新增或按明确选择更新，跳过项不变。
- 导入内容不能触发 Shell、脚本、远程 `$ref` 或任意网络请求。
