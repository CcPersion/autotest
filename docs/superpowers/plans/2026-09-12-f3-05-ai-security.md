# F3-05 AI 安全门禁实施计划

## 目标

把 AI 的“只能读脱敏事实、只能生成待确认 Patch、不能执行危险动作”从设计约束变成可回归的安全门禁。云模型只看到脱敏、截断后的上下文；提示词中的指令注入只能作为数据处理，不得扩展工具权限。

## 本轮范围

- 固定并测试 AI 工具白名单：资产元数据、脱敏报告和待确认 Patch；不存在 Runner、Shell、文件、通知、SQL 写入或自动运行工具。
- 对用户消息、模型文本、工具结果统一执行敏感值替换；对发送给模型的历史上下文和工具报告设置长度上限。
- 对 Patch 操作继续执行 JSON Pointer、业务结构、脚本/Shell、敏感字段引用和人工确认约束。
- 使用一组提示注入样本回归“错误/拒绝/待确认”三类结果，不把模型的自然语言声明当作授权。
- 记录最小安全审计证据：工具名称、结果状态和确认状态，不记录密钥明文。

## 明确不做

- 不引入新的脚本沙箱、策略引擎或 RBAC；不允许模型直接调用数据库、JMeter、Runner、Shell 或外部通知。
- 不把提示注入关键词简单粗暴地当成业务文本错误；只有进入工具参数、Patch 值或危险动作时才 fail closed。
- 不把 Fake 模型测试等同于云模型安全认证；真实模型抓包和 Playwright 部署验收仍需后续环境门禁。

## 验收条件

1. 预设提示注入样本全部不能获得未注册工具或绕过人工确认；危险/脚本 Patch 被拒绝，安全 Patch 只能返回 `PENDING_REVIEW`。
2. 模型请求、会话消息、SSE、工具结果和审计摘要中不出现密钥明文；文本和结构化报告超过上限时明确截断。
3. 未确认 Patch 不调用资产写入服务；运行、通知、Shell、SQL 写入工具调用计数为零。
4. 后端安全合同测试、真实 WSL PostgreSQL 脱敏回归和根门禁通过。
