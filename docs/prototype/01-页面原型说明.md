# AI 接口自动化测试平台页面原型说明

> 状态：V2 待用户验收（2026-09-09 已按确认方案更新）  
> 用途：作为后续正式页面开发的视觉与交互参考，不代表后端功能已经实现

## 1. 设计目标

页面采用“专业测试工作台”风格：信息清晰、操作紧凑、状态可信。视觉参考成熟开发工具的秩序感，不复制 MeterSphere 或 Postman 页面，不使用大面积渐变、玻璃拟态、悬浮光球和空洞数据大屏。

核心感受：

- 专业：接口、变量、断言、步骤和报告是页面主角。
- 克制：深墨导航、暖灰背景、白色工作面、钴蓝操作色。
- 高效：常用操作保持在当前上下文，不用多层弹窗跳转。
- 可信：成功、失败、警告和运行中状态使用稳定统一的语义色。
- AI 原生但无“AI 味”：AI 是可审阅的工作助手，不支配全部界面。

## 2. 桌面布局

- 左侧 72 像素主导航：产品标识、九个功能入口、帮助和用户。
- 顶部 56 像素上下文栏：项目、环境、全局搜索、Runner 状态和快捷运行。
- 主工作区根据功能使用双栏或三栏布局。
- 默认适配 1440 像素及以上工作屏；窄屏收起辅助栏，不以手机端为首要目标。

## 3. 视觉语言

- 主背景：暖灰 `#F4F5F7`。
- 导航背景：深墨 `#111827`。
- 主操作色：钴蓝 `#315EFB`。
- 成功、失败、警告：墨绿、朱红、琥珀，避免荧光色。
- 中文使用系统无衬线字体；代码、变量、JSON、SQL 使用等宽字体。
- 圆角控制在 6 至 12 像素；阴影只用于浮层和当前焦点。
- 图标使用统一线性 SVG，不使用表情符号充当功能图标。

## 4. 页面原型范围

1. AI 工作台：快捷意图、输入区、生成计划、差异确认和最近运行。
2. 接口管理：模块树、接口列表、请求编辑、响应与保存。
3. 接口用例：数据行、提取、断言和清理配置。
4. 场景自动化：组件栏、步骤树、属性面板与模拟运行。
5. 测试集合：成员、执行顺序、环境和回归摘要。
6. 环境配置：变量、密钥、JDBC、Redis、证书和文件。
7. 运行中心：状态筛选、运行列表和失败定位。
8. 报告详情：步骤树、请求响应、提取、断言和清理结果。
9. 系统设置：模型、Runner、JMeter 和通知状态。

## 5. 原型交互

- 主导航切换页面并保留当前上下文。
- 顶部可切换项目和环境。
- AI 输入后生成结构化建议；用户可打开差异并确认或放弃。
- 接口页面可切换参数标签并模拟请求执行。
- 场景页面可选择步骤、添加步骤并模拟运行。
- 运行中心可按状态筛选并打开报告。
- 报告页面可切换步骤和详情标签。
- 所有模拟动作明确标注“原型演示”，不伪装为真实后端执行。

## 5.1 V2 变化

- AI 工作台改为任务导航型首页，首屏明确展示“从需求创建测试、从 Curl 创建用例、导入 OpenAPI、分析失败报告”四类场景。
- AI 工作台增加“选择任务 → 提供信息 → 审阅保存”三步引导。切换任务时同步更新输入提示、示例、上下文和生成动作，原有草稿、差异查看、确认保存交互继续保留。
- AI 工作台右侧改为新手使用说明、最近任务和安全边界提示，帮助第一次进入的用户理解使用方式。
- 全站原型正文调整为不低于 14px，辅助信息不低于 12px，并同步放大标题、按钮、表格、步骤、参数和代码内容；1440×900 仍采用工作台布局，不增加横向滚动。
- 场景自动化参考 MeterSphere 的成熟信息架构，顶部提供“步骤、场景变量、前后置、设置”四个区域；步骤区使用主流程/清理流程树形层级、父子条件步骤、连接线和可展开配置。
- 场景步骤展开后可查看请求、前置、后置、提取和断言摘要；添加步骤菜单包含引用接口用例、自定义 HTTP、SQL、Redis、条件、循环、等待、清理。
- 引用接口用例时明确提供“引用/复制”模式及含义说明；右侧属性区仅展示当前步骤摘要、复用方式和运行策略；场景模拟运行与报告跳转继续保留。

## 6. 原型验收

- 九个页面均能从主导航进入。
- 1440×900 下无横向溢出，主要操作不被遮挡。
- 关键交互有明确的选中、悬停、禁用和反馈状态。
- 页面中不存在无法解释用途的大卡片或装饰性指标。
- 页面用语与产品需求保持一致，不出现租约、fencing、五类选择器和发布版本中心。
- `npm run test`、`npm run typecheck` 和 `npm run build` 通过。
