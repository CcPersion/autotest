# F4-05 实施与验收记录

## 记录边界

本记录对应 `deployment/scripts/verify-f4-05-compose.sh` 验收入口。本阶段只新增验收编排、定向门禁测试和中文记录，不修改平台 API、数据库迁移、执行内核或 Compose 业务拓扑。

验收入口必须使用独立的 Compose project，project 名称匹配 `autotest-f405-[a-z0-9-]+`。脚本统一通过同一个 project 执行 `config`、`up`、`ps`、`restart` 和 `down`，并且只清理由该 project 标签标识的容器、网络和卷；不执行 `docker prune` 或模糊删除。

## 已实现的门禁

- 启动前检查 `deployment/.env`、`E2E_ADMIN_PASSWORD`、必需配置项和仓库绝对路径边界；缺少配置时 fail-fast。
- Web/API URL 作为参数传入，并校验无凭据、query 和 fragment；未提供时分配临时端口。
- 使用 Compose JSON 快照检查 `postgres`、`platform-api`、`web`、`runner-app` 四个服务处于 `running/healthy`。
- 通过 `/api/v1/runners/status` 检查 Runner 在线心跳。
- Runner 状态检查先使用统一管理员登录得到 session cookie；服务重启并恢复健康后重新登录得到新 cookie，再要求同一 `runnerId` 的 `lastSeenAt` 严格晚于重启前基线后进行报告查询。
- project 边界枚举或 `inspect` 失败时，停止后续 Compose config、启动前清理、制品构建和 up；只生成失败证据。
- 资源枚举兼容 Docker 29：container/volume 使用 `ls -aq`，network 使用 `docker network ls -q`。
- 调用既有 Playwright 的 F1-10、F2-10 子门禁，并要求 `E2E_EXPECT_SUITE_REPORT=true`。
- 重启服务后重新检查健康状态、Runner 心跳和报告恢复。
- 定向测试使用假的 `docker` 命令覆盖显式/默认 URL、统一缺参退出码和资源查询失败的 fail-closed 路径，不启动 Compose。
- 生成 `results.json`、本中文记录、命令退出码和脱敏日志；发现敏感值时保留泄漏计数但替换证据目录中的明文，清理失败、敏感哨兵泄露或存在 BLOCKED 项时不得判定总体验收通过。
